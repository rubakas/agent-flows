## Context

Binding C (`src/bindings/n8n/build.ts`) generates n8n workflow JSON from the canon, but the generated workflows feed every model garbage while n8n reports success. Four verified gaps:

1. **Canon placeholders are emitted literally.** `buildStepNode` passes the raw prompt text straight into the `prompt` parameter (`src/bindings/n8n/build.ts:81`), leaving canon `{{key}}` placeholders in place, and the value does not start with `=` — so n8n stores it as a plain string, never an expression (expressions are exactly the string values whose first char is `=`: `isExpression`, [expression-helpers.ts](https://github.com/n8n-io/n8n/blob/master/packages/workflow/src/expressions/expression-helpers.ts), consumed by `resolveSimpleParameterValue`, which strips the `=` and evaluates the rest as a `{{ }}` template — [expression.ts](https://github.com/n8n-io/n8n/blob/master/packages/workflow/src/expression.ts)). In the freshly generated `.n8n-workflows/investigate.json`, the `survey` node's prompt contains the literal text `Request: {{request}}` (`:30`) and the `findings` node's prompt contains the literal `{{survey}}` (`:48`). At run time the first model receives the string `{{request}}` instead of the request and the second receives `{{survey}}` instead of the survey — silently green and wrong, worse than the visibly-placeholder NoOp nodes. The TODO at `build.ts:74` acknowledges this; `WORKSPACE_DIR_EXPR = "={{ $json.projectDir }}"` (`build.ts:17`) shows the file already uses expression form elsewhere — only prompts were left behind.

2. **There is no way to supply the pipeline's declared inputs.** The graph starts at a bare `n8n-nodes-base.manualTrigger` (`build.ts:19`, `:155`) that produces no `projectDir` and no `request`, so even `WORKSPACE_DIR_EXPR` resolves to undefined today.

3. **`$json.projectDir` is wrong beyond level 0.** `$json` is the current node's input item; for a level-1 step that item is the upstream agent node's output (`{role, model, workspaceAccess, output, exitCode}` — `integrations/n8n-nodes-agent-flows/src/nodes/YokeAgent/YokeAgent.node.ts:417-424`), which has no `projectDir`.

4. **Generated parameter names do not match the node.** Build emits `contentsAccess`, `workspaceDir`, and `skills` (`build.ts:78-80`); the node declares `workspaceAccess` (`YokeAgent.node.ts:314`), `workspaceDirectory` (`:334`), and no `skills` property at all (`:278-363`). The node therefore reads its defaults — `workspaceDirectory` comes back empty and every generated llm step dies at `workspaceDirectory is required when workspaceAccess is "read"` (`:395-396`). Interpolated expressions are useless if they sit under keys the node never reads, so this alignment is in scope.

Research established the target n8n semantics (all checked 2026-09-07):

- **Referencing a named upstream node**: `$('<node-name>')` with `.item` ("the linked item… used to produce the current item"), `.first(branchIndex?, runIndex?)`, `.last()`, `.all()`; data under `.json` ([reference-previous-nodes](https://docs.n8n.io/build/work-with-data/reference-data/reference-previous-nodes.md)). The node name is always a quoted string argument, so dotted step ids from nested-pipeline expansion (`src/canon/nest.ts:25`) need no escaping beyond normal JS string quoting.
- **Expression mode**: leading `=` (source citations above); inside the value, text outside `{{ }}` is literal and `{{ }}` regions are evaluated; multi-statement code is allowed via an IIFE ([expressions-for-data-transformation](https://docs.n8n.io/build/work-with-data/transform-data/expressions-for-data-transformation.md)).
- **Escaping literal braces is undocumented.** Neither the expressions guide nor the [expression reference](https://docs.n8n.io/build/work-with-data/transform-data/expression-reference.md) documents an escape for a literal `{{`; the evaluator, [tournament](https://github.com/n8n-io/tournament), is "an output-compatible rewrite of `riot-tmpl`" and documents no escape either. (A community attempt at `{{ '{' }}` failed with "Single '}' in template" — [topic 32424](https://community.n8n.io/t/requesting-json-output-from-chatgpt-escaping-curly-braces/32424) — though that error came from the AI-node's LangChain templating, not core expressions; the point stands that no documented escape exists.) The design below therefore never relies on brace escaping semantics.
- **The agent node's output key** is `output` (plus `role`, `model`, `workspaceAccess`, `exitCode`) — `YokeAgent.node.ts:417-424`. A `check` step is an `n8n-nodes-base.executeCommand` node (`build.ts:86-89`) whose output is `{exitCode, stderr, stdout}` ([ExecuteCommand.node.ts](https://github.com/n8n-io/n8n/blob/master/packages/nodes-base/nodes/ExecuteCommand/ExecuteCommand.node.ts)).
- **Supplying inputs**: the Edit Fields (Set) node "can set new data as well as overwrite data that already exists" and its values are editable in the n8n UI with a Fixed/Expression toggle ([n8n-nodes-base.set](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.set.md)). The alternative, an Execute Sub-workflow Trigger with declared workflow inputs, "runs in response to a call from the Execute Sub-workflow… nodes" and has no first-class way to type values for a manual run ([executeworkflowtrigger](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.executeworkflowtrigger.md)).

## Functional Requirements

| ID     | Requirement |
| ------ | ---- |
| FR-001 | The generated graph gains an `Inputs` node (`n8n-nodes-base.set`) wired `Manual Trigger → Inputs → every level-0 step` (replacing the direct trigger→level-0 edges built at `build.ts:167-172`). It defines one string field per declared pipeline input (`def.inputs`, `src/canon/types.ts:161`) plus `projectDir`, each defaulting to `""`. The operator's run story is: open the workflow, open `Inputs`, type the request and project directory, click Execute Workflow. |
| FR-002 | Canon placeholders in llm prompts are rewritten to n8n expressions using the canon's own pattern (`/\{\{([\w.]+)\}\}/g`, `src/canon/render.ts:8`): a pipeline input `k` → `$('Inputs').first().json[<JSON.stringify(k)>]`; an ancestor llm step `s` → `$(<JSON.stringify(s)>).first().json.output`; an ancestor check step `c` → `$(<JSON.stringify(c)>).first().json.stdout`. `JSON.stringify` on names makes dotted ids (`verify.synthesis`) and any future odd characters safe by construction. `.first()` is chosen over `.item` because generated graphs are strictly single-item and `.first()` avoids paired-item resolution as a failure mode. |
| FR-003 | A prompt containing at least one placeholder is emitted as `=` + mixed template (literal text with `{{ ref }}` regions). In such prompts, every *other* literal `{` and `}` in the text is replaced by `{{ String.fromCharCode(123) }}` / `{{ String.fromCharCode(125) }}`, so the literal segments contain no brace characters at all — correctness never depends on undocumented escaping. A prompt with no placeholders stays a plain (non-`=`) string, which n8n never evaluates; if such a prompt happens to start with `=`, it is wrapped as `={{ <JSON.stringify(text)> }}` to prevent accidental expression mode. `check` commands (`build.ts:87`) remain plain strings. |
| FR-004 | `WORKSPACE_DIR_EXPR` (`build.ts:17`) becomes `={{ $('Inputs').first().json.projectDir }}` so every node, at any level, resolves the directory set once in `Inputs`. |
| FR-005 | Emitted llm parameters are renamed to what the node actually reads: `workspaceAccess` (was `contentsAccess`, `build.ts:78`), `workspaceDirectory` (was `workspaceDir`, `:79`); the unknown `skills` key (`:80`) is dropped. Values are unchanged (`read`/`none` already match the node's options, `YokeAgent.node.ts:316-329`). |
| FR-006 | Generation fails loudly — a thrown error naming the referencing step, the placeholder, and the target step's kind — when a placeholder references a step Binding C emits as a NoOp (`gate`, `loop`, `export-spec`, `assemble-spec`, `persist-ticket`; `build.ts:91-120`) or the `models` context key (`src/canon/load.ts:366`; no canon prompt uses it today — repo-wide grep, 2026-09-07). A NoOp passes its input through, so the reference would silently resolve to the *wrong upstream's* data; refusing to generate is the only honest behaviour. The error text states that this pipeline needs those step kinds implemented in Binding C first. |
| FR-007 | Generation fails with a clear error if any step id collides with the reserved node names `Manual Trigger` or `Inputs` (n8n node names must be unique; a collision would silently rewire references). |
| FR-008 | The committed `.n8n-workflows/*.json` artifacts are regenerated; any pipeline that now fails under FR-006 has its stale artifact deleted rather than left as silently-broken JSON. |

## Design

**Input entry (FR-001).** Committed choice: keep the Manual Trigger, insert a Set/Edit Fields `Inputs` node. Rejected alternative: Execute Sub-workflow Trigger with declared inputs — it is built for being *called* by another workflow, and the docs offer no way to just type values and hit run (loading test data is plan-gated); it fails the "operator opens this in n8n, types a request, hits run" test. The Set node's values are plain editable fields in the UI, which *is* that test. `optionalInputs` (`src/canon/types.ts:163`) need no special handling: an empty string field is a legitimate "omitted" value; the prompt simply interpolates emptiness, same as today's Binding B contract. The exact JSON serialization of the Set node's fields varies by `typeVersion`; implementation captures it by hand-building the node in n8n once and exporting (test plan §7) rather than trusting undocumented internals — `makeNode`'s hardcoded `typeVersion: 1` (`build.ts:67`) must be overridable for this one node.

**Placeholder mapping (FR-002/FR-003).** The load-bearing decision is *never relying on brace escaping*. Two alternatives were considered for arbitrary prompt text: (a) emit the whole prompt as one `{{ [...].join('') }}` expression over JSON-stringified segments — rejected because a prompt body containing `}}` (example code, JSON) could terminate the template region early, and tournament's tokenizer behaviour inside string literals is undocumented; (b) mixed template with `String.fromCharCode` replacement for stray braces — chosen, because after replacement the literal segments contain no brace characters whatsoever, so no tokenizer, however naive, can mis-split them, and prompts without stray braces stay fully readable in the n8n editor. Kind-aware target fields (llm→`output`, check→`stdout`) come from the generator's own `StepDef` knowledge; the placeholder validation already performed at load time (`src/canon/load.ts:362-377`) guarantees every placeholder is a declared input or transitive ancestor id, so the generator's classification is total.

**Failure design (FR-006/FR-007).** Generation-time errors, not runtime markers. An IIFE that throws at runtime is possible (the docs document IIFEs in expressions) but was rejected: it ships a workflow known to be broken and defers the bad news to a mid-run crash. Refusing to emit the file, with an error naming exactly which placeholder cannot be honoured and why, keeps the invariant this spec exists to establish: *a generated workflow that imports and runs green actually ran the pipeline*. Cost: some pipelines that generate today (uselessly) will stop generating until the NoOp kinds are implemented — stated in Backward compatibility.

**Change surface.** All changes land in `src/bindings/n8n/build.ts` plus a sibling helper/test file; nothing in `integrations/n8n-nodes-agent-flows` changes (the node's `output` key and parameter names are consumed as-is). No new dependencies.

## Backward compatibility

- `generateN8nWorkflow`'s signature and the `N8nWorkflow` shape (`build.ts:42-49`) are unchanged; workflows gain one node and renamed llm parameters. n8n import is unaffected.
- Previously generated `.n8n-workflows/*.json` are superseded; regeneration (FR-008) is part of the change. No runtime consumer parses these files today except n8n itself.
- Intentional break: pipelines whose prompts reference gate/loop/export-spec/assemble-spec/persist-ticket steps now fail to generate (FR-006) instead of producing silently-wrong JSON.
- Bindings A/B, the canon loader, and `renderPrompt` are untouched; the canon `{{key}}` syntax remains the single authoring format.

## Out of scope

- Implementing gate, loop, export-spec, assemble-spec, or persist-ticket as real n8n nodes — the NoOp TODOs (`build.ts:92`, `:97`, `:108`, `:119`) stay open; this spec only stops them from corrupting llm steps that reference them.
- Deleting or keeping Binding C — owner's open decision, explicitly not prejudged here.
- Supporting the `{{models}}` placeholder in Binding C (no prompt uses it; FR-006 rejects it loudly).
- Adding `skills` or `timeoutMs` support to the n8n node; multi-item execution semantics.
- Any change to Binding B's rendering (`src/bindings/mastra/buildSteps.ts:147`) or the canon placeholder grammar.

## Test plan

1. **Input mapping** — a prompt `Request: {{request}}` with `request ∈ def.inputs` yields a `prompt` starting with `=` and containing `{{ $('Inputs').first().json["request"] }}`; the literal text around it is unchanged.
2. **Step mapping, dotted id** — `{{verify.synthesis}}` where `verify.synthesis` is an llm step yields `{{ $("verify.synthesis").first().json.output }}`; a check-step reference yields `.json.stdout`.
3. **Escaping** — a placeholder-bearing prompt containing a stray `{` and `}` (e.g. a JSON example) emits them as `{{ String.fromCharCode(123) }}` / `{{ String.fromCharCode(125) }}`, and the emitted literal segments contain no brace characters; a placeholder-free prompt is emitted as a plain string byte-identical to the canon prompt; a placeholder-free prompt starting with `=` is wrapped as `={{ "..." }}`.
4. **Loud failure** — a prompt referencing a gate step id makes `generateN8nWorkflow` throw, and the message contains the referencing step id, the placeholder, and the word `gate`; same for `{{models}}`; a step literally named `Inputs` also throws (FR-007).
5. **Graph shape** — generated `investigate` contains `Manual Trigger → Inputs → survey → findings`; the `Inputs` node has fields `request` and `projectDir`; `survey`/`findings` carry `workspaceAccess`/`workspaceDirectory` keys and no `contentsAccess`/`workspaceDir`/`skills`.
6. **Regenerated artifacts** — `.n8n-workflows/investigate.json` no longer contains the literal substrings `Request: {{request}}` or a bare `{{survey}}` outside an expression, and its `workspaceDirectory` values reference `$('Inputs')`.
7. **Manual e2e in n8n** — import regenerated `investigate.json` into a live n8n with the agent-flows node installed; type a request and a real repo path into `Inputs`; execute. Verify in the execution view that `survey` received the typed request text (not `{{request}}`) and `findings` received `survey`'s actual output. This run also captures the authoritative Set-node parameter serialization for the chosen `typeVersion` (see Design).
